## 1. Введение: Почему массивы плохи для строк?

Давайте мысленно вернемся к обычному массиву или даже к сбалансированному бинарному дереву поиска.

Предположим, нам нужно хранить словарь английского языка (200 тысяч слов) и быстро проверять, есть ли слово в словаре.

*   **Массив:** Бинарный поиск — \( O(\log N) \), то есть около 18 сравнений. Неплохо. Но что именно сравнивается? Сравнение двух длинных строк (`"Internationalization"` c `"Interoperability"`) может идти посимвольно.
*   **Хеш-таблица:** Почти мгновенно: \( O(1) \) в среднем. Так зачем нам что-то еще?

**Проблема:**
1.  **Коллизии:** Хеш-функции дают осечки.
2.  **Память:** Хранение длинных ключей целиком.
3.  **Главный козырь деревьев:** Операции с префиксами.

*Как в массиве найти все слова, начинающиеся на "hel"?* Никак, кроме полного перебора. А в телефоне (T9, автодополнение) это работает мгновенно.

Сегодня мы изучим структуру данных, которая хранит не слова, а **буквы**, и позволяет делать поиск по префиксу за \( O(L) \), где \( L \) — длина самого префикса. Называется она **Префиксное дерево** (Trie, произносится «трай», от слова Re**trie**val, или просто «Бор»).

---

## 2. Структура и геометрия данных

Префиксное дерево — это не бинарное дерево. Каждый узел может иметь **много** потомков (обычно до 26 для латиницы, до 33 для кириллицы или 256 для ASCII).

**Правила игры:**
1.  **Корень:** пустой узел, не обозначает никакой буквы.
2.  **Ребра (связи):** обозначают ровно один символ. Мы рисуем стрелку и подписываем её буквой.
3.  **Узлы:** представляют собой накопленный префикс.
4.  **Терминальный флаг:** в узле должно храниться свойство «Здесь заканчивается слово».

*Если слово есть в дереве, мы можем пройти от корня по буквам, и последний узел будет помечен как конечный.*

**Пример для слов: "he", "hello", "hi", "hip".**

```
         [ROOT]
        /      \
      h          ...
     / \
    e*  i*
   /    / \
  l    p*   ...
 / \
l   ...
|
o*
```

*   Узел `e` и `i` помечены звездочкой — они концы слов `he` и `hi`.
*   Узел `p` — конец слова `hip`.
*   Узел `o` — конец слова `hello`.
*   Узел `l` между `e` и `o` звездочки не имеет, так как слово "hel" в словаре не числится.

> Чтобы найти слово, нам нужно сделать ровно столько шагов, сколько букв в слове. Длина слов "Internationalization" (20 букв) — это наша константа \( L \). Сложность поиска **не зависит** от количества слов в словаре \( N \). Это \( O(L) \).

## 3. Реализация 

Договоримся, что работаем с алфавитом английских строчных букв (`'a'` - `'z'`). Размер алфавита `ALPHABET_SIZE = 26`.

В связном списке у нас была структура `Node` с полем `data` и указателем `next`.
Здесь нам понадобится немного другая структура.

### 3.1. Узел дерева

Нам не нужны связные списки для хранения детей. Самый быстрый (хотя и прожорливый по памяти) способ — массив указателей фиксированного размера.

```cpp
#include <iostream>
#include <string>

const int ALPHABET_SIZE = 26;

// Структура одного узла
struct TrieNode {
    TrieNode* children[ALPHABET_SIZE]; // Массив указателей на детей
    bool isEndOfWord;                  // Терминальный флаг

    // Конструктор (зануляем массив и флаг)
    TrieNode() {
        isEndOfWord = false;
        for (int i = 0; i < ALPHABET_SIZE; ++i) {
            children[i] = nullptr;
        }
    }
};
```

*Сравнение со связным списком:* В `ListNode` было одно поле `next`. Здесь у нас их 26. Это плата за скорость.

### 3.2. Вспомогательная функция - перевод символа в индекс

Чтобы не путаться, вынесем это в хелпер:

```cpp
int charToIndex(char ch) {
    return ch - 'a'; // 'a' -> 0, 'b' -> 1, ..., 'z' -> 25
}
```

### 3.3. Операция Вставка (Insert)

Логика такая же, как проход по односвязному списку, только мы не перебираем элементы, а «создаем дорогу».

1.  Встаем в корень (`root`).
2.  Для каждой буквы слова:
    *   Смотрим на нужную ветку (индекс буквы).
    *   Если указатель `nullptr` — создаем новый узел.
    *   Переходим в этот узел.
3.  В конце пути ставим `isEndOfWord = true`.

```cpp
void insert(TrieNode* root, const std::string& word) {
    TrieNode* current = root;
    
    for (char ch : word) {
        int index = charToIndex(ch);
        
        // Если пути нет - строим
        if (current->children[index] == nullptr) {
            current->children[index] = new TrieNode();
        }
        
        // Идем глубже
        current = current->children[index];
    }
    
    // Помечаем конец слова
    current->isEndOfWord = true;
}
```

> Вставляем слово "cat". Создаем узлы `c -> a -> t`. Теперь вставляем слово "car". Проходим `c -> a`, на букве `r` видим `nullptr`, создаем узел `r`. Теперь у узла `a` два ребенка: `t` и `r`.

## 4. Основные виды поиска

У префиксного дерева три ключевых поисковых операции, которых нет у массива.

### 4.1. Точный поиск (Search)
Проверяем, есть ли слово в словаре целиком.

```cpp
bool search(TrieNode* root, const std::string& word) {
    TrieNode* current = root;
    
    for (char ch : word) {
        int index = charToIndex(ch);
        
        // Если в какой-то момент дороги нет - слово не найдено
        if (current->children[index] == nullptr) {
            return false;
        }
        current = current->children[index];
    }
    
    // Прошли все буквы. Является ли этот узел концом слова?
    return (current != nullptr && current->isEndOfWord);
}
```

> Что вернет `search("ca")`, если мы вставили только "cat" и "car"? `false`. Флаг `isEndOfWord` у узла `a` не установлен. Мы прошли по дереву успешно, но это чужое «серединное» состояние.

### 4.2. Проверка префикса (StartsWith)
Главная фишка структуры. Проверяем, есть ли в дереве хоть одно слово, начинающееся с заданной строки.

Отличие от `search` минимально: нам все равно на флаг `isEndOfWord` в конце. Главное, что мы нигде не споткнулись о `nullptr`.

```cpp
bool startsWith(TrieNode* root, const std::string& prefix) {
    TrieNode* current = root;
    
    for (char ch : prefix) {
        int index = charToIndex(ch);
        if (current->children[index] == nullptr) {
            return false;
        }
        current = current->children[index];
    }
    
    // Прошли префикс без падений -> true
    return true;
}
```

### 4.3. Автодополнение
Если бы нам нужно было вывести все слова, начинающиеся с "hel":
1.  Спускаемся к узлу "hel" с помощью `startsWith`.
2.  Оказавшись в этом узле, запускаем обход в глубину (DFS) по всем 26 веткам.
3.  Как только встречаем `isEndOfWord == true`, печатаем накопленный путь.
*Сложность:* \( O(26 \cdot K) \), где \( K \) — количество букв во всех словах с этим префиксом.

## 5. Сравнение с другими структурами

Давайте подведем итог и составим таблицу. Пусть \( N \) — количество слов в словаре, \( L \) — длина слова/ключа.

| Операция | Массив (+ бин. поиск) | Хеш-таблица | Префиксное дерево (Trie) |
| :--- | :--- | :--- | :--- |
| **Поиск слова** | \( O(L \cdot \log N) \) | \( O(L) \) в среднем / \( O(N \cdot L) \) в худшем | \( O(L) \) — гарантированно |
| **Вставка слова** | \( O(N) \) (сдвиг) | \( O(L) \) | \( O(L) \) |
| **Поиск по префиксу** | \( O(N \cdot L) \) (полный скан) | **Невозможен** | \( O(L) \) |
| **Память** | \( N \cdot L \) | \( N \cdot L \) + оверхед | Огромный оверхед (26 указателей на узел), но существуют сжатые версии (Radix Tree). |

---

## 6. Очистка памяти

Так как мы используем динамическую память (`new`), мы обязаны её освободить. Процедура похожа на удаление бинарного дерева: рекурсивно удаляем детей.

```cpp
void deleteTrie(TrieNode* node) {
    if (node == nullptr) return;
    
    for (int i = 0; i < ALPHABET_SIZE; ++i) {
        if (node->children[i] != nullptr) {
            deleteTrie(node->children[i]);
        }
    }
    
    delete node; // Удаляем сам узел
}
```

## 7. Заключение

1.  **Trie (Бор)** — это специализированная структура для строк. Он бесполезен для обычной сортировки (как Куча).
2.  Ключевая особенность — **общий префикс**. Слова "cat" и "car" хранят "ca" в памяти один раз, в отличие от массива, где это две разные строчки.
3.  **Асимптотика** здесь привязана к длине слова, а не к размеру базы данных. В словаре из 10 миллионов слов поиск "hello" все равно займет 5 шагов.
4.  Это основа для систем орфографии, T9 на кнопочных телефонах, поисковых подсказок и роутеров (префиксные маски IP-адресов).
